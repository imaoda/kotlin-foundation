# 0001：采用现有机制，补足长期对象的同步所有权契约

状态：v0.1 实现决定；日期：2026-10-19。

目标是纯逻辑对象的组织与协作，同时为人和 AI 提供可靠能力入口。数据和业务行为由普通 Kotlin 对象封装，资源所有权明确；不扩展到 UI、宿主集成、全局 DI 或跨语言通用接口。

## 复用优先

stdlib 已有 AutoCloseable/use；协程已提供状态、任务及异步广播；Arrow 提供类型化错误和异步资源组合；Reaktive 提供 Disposable 集合；Essenty 提供相邻生命周期能力。见 [providers](../providers/index.md)。

保留自研候选的依据是整套契约，而非“生态没有轮子”：

- AutoCloseable 的长期动态集合需要终态、逆序清理、独立提前释放、初始化回滚模式。
- ManagedComponent 提供推荐 OOP 所有权路径和 final close，不要求使用者覆写后调用 super。
- CloseableSlot 为动态替换句柄提供一致所有权转移；与主资源组不能双重登记同一资源。
- 同步 Event 需要即时注册、调用栈内通知、独立取消；SharedFlow 的调度和缓冲语义不同。仅提供通知，不重造流操作符。

这些原语使用标准接口，避免为了一个组件要求引入完整响应式/框架体系。已有对应生态的用户可以直接采用其库，本项目保留对照和迁移边界；不是一律主张替换。

## 保持小范围

核心只依赖 stdlib。取消、错误、异步关闭首先以原生能力和经过测试的实践提供。暂不提供通用异步基类、公共 FailureReporter、ErrorCode/Result DSL、own(Job)、UI/宿主适配。

公共 API 为预发布。同步操作要求调用方串行访问，不宣称跨线程安全或自动证明唯一所有权。该限制使 v0.1 不隐藏调度成本；未来并发需求应独立评审，不能默默改变回调线程或完成承诺。
