# 0002：事件与同步终态

状态：v0.1 实现决定；日期：2026-10-19。

事件发布器创建时必须显式选择 FailFast 或 ReportAndContinue。前者立即传播并结束当前派发，后者要求失败回调；两者都不承诺恢复取消和 fatal failure。报告器自身失败时保留原始监听异常并终止派发。

事件只表达已发生事实，不承担事务提交或回滚。派发在调用栈中执行，重入采用深度优先；每次派发使用快照，已取消但尚未开始的监听跳过，新监听在下一次（含嵌套）派发可见。关闭发布器不销毁监听者业务对象。

同步资源关闭先进入终态，再执行清理。重入close无操作；逆序释放，保留清理异常。关闭后登记的新资源必须获得清理并明确拒绝，不能返回一个看似可用的已关闭资源。具体异常与引用处理以公开KDoc和契约测试为准。

这些行为都是项目自己的设计选择，不声称是 Kotlin 生态唯一规则。它们的改变属于公开行为变更，必须与代码、测试、实践同时审查。
