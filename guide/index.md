# 使用入口：面向人和 AI

本入口指导如何使用 kotlin-foundation。先遵守使用方项目的规则，再明确采用哪些规范；不要把本仓库的维护 AGENTS.md 注入使用方工程。

## 按需读取

1. 确认业务对象的职责、所有者、借用依赖和结束时机，阅读 [架构规范](../architecture/)。
2. 从 [能力索引](../capabilities/index.md) 找到当前问题。先用默认路径，只有条目中的切换条件成立时才改用替代方案。
3. 查看提供方的版本与证据，不把上游支持声明当成本项目实测。
4. 阅读对应 [实践与源代码](../practices/)，保留其取消、重入、错误和线程约束。
5. 在使用方做相应验证，记录未验证部分。发现缺口先查现成方案，再提出适配或自研；不要自动添加目录里所有依赖。

## 采用方式

- **只采用规范**：引用此入口和适用条目，直接使用 Kotlin 标准库、协程或社区库。
- **采用组件**：按 [开发说明](development.md) 构建/消费 core；先阅读其 KDoc 和约束。
- **采用整体对象模型**：长期持有同步资源的业务对象默认继承 ManagedComponent。值对象、状态快照和纯计算保持普通 Kotlin 类型。

所有权树、服务依赖、事件订阅、任务树和故障边界分别表达。订阅方拥有解绑句柄；发布方结束可使句柄失效，但不拥有也不销毁订阅方的业务对象。

## 版本与维护

使用方应引用明确的 tag/commit 与依赖版本。此处文档与该版本代码一起演进，不假设网上 main 分支适配旧版本。版本核验记录位于 [兼容性证据](../providers/compatibility.md)。

新增公共能力需说明真实场景、成熟方案不足、契约和验证；库名相似或当前仓库没有代码，都不是自研理由。
